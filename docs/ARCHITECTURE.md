# ARCHITECTURE｜nukumori 構成

最終更新：2026-10-31（9章を「決めたこと」に書き換え）
この文書はコードを含まない。構成と理由だけを書く。実装は 2026-11-02 12:00 JST 以降。

## 1. 全体

```
スマホのブラウザ（PWA）
  GitHub Pages で配信。HTML / CSS / JS / マニフェスト / アイコン
      │  HTTPS。写真（縮小済み）と回答を JSON で送る
      ▼
Cloudflare Workers（API の中継）
  受け取った内容を点検し、システムプロンプトを足して Claude API を呼ぶ
  API キーはここにだけある（Workers のシークレット）
      │  HTTPS
      ▼
Claude API（Anthropic）
```

- 置き場所は2つだけ。データベースもサーバーも持たない
- 写真と回答は、Workers を通り抜けるだけで保存しない。Claude API への送信も診断の1回のみ

## 2. PWA（GitHub Pages）の受け持ち

- 画面（docs/SCREENS.md）のすべて
- 親の一言からの「場所」「時間帯」の取り出し（簡単な語の照合）
- 写真の縮小（端末内。長辺 1,000〜1,200 px、JPEG）。理由は4章
- ルールで決める部分（docs/LOGIC.md の3章）。端末側で計算して Workers に渡す。Workers 側に置いてもよいが、画面で「建築士の一次判断」として先に見せられるので端末側に置く
- 結果の表示と端末内保存（ブラウザの保存領域）
- PWA の最低限：マニフェストとアイコン、ホーム画面への追加。オフライン動作は MVP では求めない（診断に通信が要るため）
- ビルド工程を持たない静的ファイルで始める。フレームワークは使わないか、使うとしてもビルド不要のものにする。理由：8日間で動かすこと、GitHub Pages への配置を単純にすること
- GitHub Pages の公開はリポジトリを公開にするか、GitHub の有料プランでの非公開リポジトリからの公開になる。提出時に公開にする前提で、公開して困るものをリポジトリに入れない（API キー、個人情報、会社の情報）

## 3. Cloudflare Workers の受け持ち

- 受け口は2つ（2026-11-04 に対話型へ変えて1つ足した）。POST /ask は、写真と固定の3問を読んで次に聞く2〜3問を選ぶ。POST /diagnose は、選んだ問いの答えを加えて診断する。写真と固定の答えは2回とも同じ並び・同じバイト列で先に置き、その直後に cache_control を付ける。システムプロンプトと写真が2回目はプロンプトキャッシュから読まれ、写真の分の入力料金が2回かからない（出力の形（JSON スキーマ）は呼び出しごとに違うが、キャッシュはメッセージの先頭から一致する分に効くので支障はない）。/ask が失敗したときは、画面が固定の順で全問を聞く（前の形に戻る）
- 受け取った内容の点検
  - 呼び出し元の確認：GitHub Pages のオリジンからだけ受け付ける（CORS の許可オリジンを1つに絞る）
  - 大きさの上限：写真は1枚あたりの大きさと枚数（最大5枚）、本文の長さに上限を置く
  - 回数の上限：同じ IP からの短時間の連打を止める（Workers の機能か簡単な数え方で）。ハッカソンの審査で使われることを考え、厳しすぎない値にする
- システムプロンプト（docs/LOGIC.md の 2.2）を足して Claude API を呼ぶ。システムプロンプトは Workers 側に置く。理由：画面側に置くと誰でも書き換えて送れるため
- Claude の返答（JSON）を点検して画面に返す。壊れていたら画面に「もう一度」を出せる形で返す
- 記録：写真と回答は記録しない。残すのは呼び出しの時刻・成否・使ったトークン数だけ（料金の見積りのため）
- API キーの扱いは5章

## 4. 写真の扱い

- 端末で縮小してから送る。理由は3つ
  1. 通信量：スマホの写真は数 MB ある。縮小すれば数百 KB になる
  2. 料金：Claude は画像を 28×28 px の区画（視覚トークン）で数える。画像のトークン数はおおむね「横 ÷ 28 の切り上げ × 縦 ÷ 28 の切り上げ」。長辺 1,000 px 程度なら 1,300 トークン前後に収まる。Claude 4.7 以降のモデルは長辺 2,576 px・4,784 トークンまで高解像度で扱うため、縮小しないと1枚あたりのトークン数が3倍近くまで増える（出典：Claude Developer Platform「Vision」 https://platform.claude.com/docs/en/build-with-claude/vision ）
  3. 保存しない方針との相性：大きな元データを外に出さない
- 対応形式は JPEG・PNG・GIF・WebP。1枚の上限は Claude API 直接で 10 MB、画像の最大寸法は 8,000×8,000 px（同上）。アプリ側の上限はこれよりずっと小さく置く
- 画像のメタデータ（位置情報など）は Claude に渡らない（同上の FAQ）。それでも端末側で縮小し直す時点で落ちる
- 送り方は base64 で本文に埋める（1回きりの診断で、使い回さないため Files API は使わない）
- 画像を先、文章を後の順で渡すと結果が良いとされる（同上）。複数枚には「写真1：窓」のようなラベルを添える

## 5. API キーを Workers にだけ置く理由と方法

### 理由

- ブラウザに置いたキーは、誰でも開発者ツールで取り出せる。GitHub Pages は静的配信なので、画面側に秘密は置けない
- リポジトリに置くと、公開した瞬間に漏れる。提出時に公開にする前提なので、最初から入れない
- Workers はサーバー側で動くので、キーは利用者に見えない。Workers からだけ Claude API を呼べば、キーの置き場所は1か所で済む

### 方法（考え方。コマンドは開発時に公式手順を見て打つ）

- Cloudflare の公式手順に従い、Wrangler の secret の機能でキーを Workers に登録する。登録したキーは Workers の中で環境変数として読めるが、ダッシュボードやコマンドからは値を読み返せない
- ローカルで動かすときは、Wrangler が読む .dev.vars ファイルにキーを置く。このファイルは .gitignore で除外済み（.env 系も除外済み）
- 設定ファイル（wrangler.toml など）にキーを書かない。必要な秘密の名前だけを宣言しておくと、未設定のまま配備したときに失敗して気づける（公式手順にその仕組みの記載あり）
- 出典：Cloudflare Workers「Secrets」 https://developers.cloudflare.com/workers/configuration/secrets/
- 万一漏れたときの手順も決めておく：Anthropic のコンソールでキーを無効にして作り直し、Workers の secret を入れ替える

### Workers 側で守ること

- 許可オリジンを GitHub Pages のオリジン1つに絞る
- 1回の呼び出しで使えるトークンの上限を置く（max_tokens と入力の大きさ）
- 連打の上限を置く
- 誤って写真や回答をログに出さない

## 6. モデルの候補（Claude 5 世代。写真を見るので Vision 対応のもの）

確認時点：2026-10-17。料金は Anthropic の API の定価（100万トークンあたり、米ドル）。最新は公式の料金ページで確認する https://platform.claude.com/docs/en/about-claude/pricing

| モデル | モデル ID | 入力 | 出力 | 位置づけ |
|---|---|---|---|---|
| Claude Opus 5.5 | claude-opus-5-5 | 4.00 | 20.00 | 第一候補。写真の読み取りと説明文の質を優先する |
| Claude Sonnet 5.5 | claude-sonnet-5-5 | 2.00 | 10.00 | 第二候補。速さと料金のバランス |
| Claude Haiku 5.5 | claude-haiku-5-5 | 0.10 | 0.50 | 補助的な処理（一言からの場所の取り出しなど）に使うなら |

- いずれも画像入力に対応し、コンテキストは 100万トークン。Claude 4.7 以降は高解像度の画像を扱える（4章）
- 第一候補を Opus 5.5 にする理由：診断の説明文の質と、写真からサッシやガラスの手がかりを読む精度が、このアプリの価値そのもの。1回の診断の料金は数円〜十数円の見込み（7章）で、ハッカソンの規模なら料金差より質を取る
- 開発中に同じ入力で Opus 5.5 と Sonnet 5.5 を比べ、差が小さければ Sonnet 5.5 に落とす。比べた結果は docs/PROJECT_STATE.md のテスト結果に書く
- Claude 5 世代の API で気をつけること（実装前に公式の移行ガイドで確かめる）
  - 思考（thinking）は常に有効で、無効にできない。深さは effort で調節する。短い診断なら低め、写真が多いときは中程度を試す
  - 決まった形（JSON）で受け取るには structured outputs（出力の形の指定）を使う。アシスタントの発話の先頭を書いておく手法（prefill）は使えない
  - ツールの強制呼び出しは使えない。このアプリではツールを使わない予定なので影響は小さい
  - 安全のための分類器が応答を断ることがある（stop_reason が refusal）。家の写真で起きる可能性は低いが、起きたときに画面で「もう一度」を出せるようにする
  - 出典：Claude Developer Platform モデル一覧と移行ガイド https://platform.claude.com/docs/en/about-claude/models/overview

## 7. 料金の見積りの考え方

1回の診断で送る量と受け取る量を見積もり、単価を掛ける。数字は目安で、開発中に実測して置き換える。

### 1回の診断の内訳（見込み）

| 項目 | 量（トークン） | 根拠 |
|---|---|---|
| システムプロンプト（役割・候補一覧・出典の要点・出力の形） | 3,000〜5,000 | 文章量から。開発中に count_tokens で実測 |
| 質問の答えとルールの一次判断 | 500 前後 | 短い JSON |
| 写真 5枚（長辺 1,000 px 程度に縮小） | 1枚 1,300 前後 × 5 = 6,500 前後 | 4章の計算式 |
| 出力（原因・改修案・確認事項・声かけ。JSON） | 1,500〜3,000 | 文章量から |

- 入力 約 10,000〜12,000、出力 約 2,000〜3,000 と見る
- Opus 5.5：入力 12,000 × 4.00 ÷ 1,000,000 = 0.048 ドル、出力 3,000 × 20.00 ÷ 1,000,000 = 0.06 ドル。合計 約 0.11 ドル（約 16〜17 円。為替による）
- Sonnet 5.5：同じ量で 約 0.054 ドル
- 写真なしなら入力が半分以下になる

### 減らせるところ

- プロンプトキャッシュ：システムプロンプトは毎回同じ文面なので、先頭に置いてキャッシュの対象にする。キャッシュから読む分の単価は通常の入力より安い。効き方は公式の説明に従う https://platform.claude.com/docs/en/build-with-claude/prompt-caching
- 写真の縮小（4章）
- effort を低めから試す

### 上限の置き方

- Anthropic のコンソールで月の使用上限を設定する
- ハッカソン期間の見込み：開発中の試行 300 回 + 審査・デモ 100 回 = 400 回 × 0.11 ドル = 約 44 ドル（Opus 5.5 のとき）。上限はこの2倍程度に置く
- Workers 側の連打の上限で、想定外の使われ方を止める

## 8. 配備の流れ（考え方）

1. GitHub のリポジトリの main を GitHub Pages の配信元にする（docs/ ではなく、画面のファイルを置く場所を別に決める。docs/ は文書用）
2. Cloudflare のアカウントで Workers を1つ作り、secret にキーを登録し、配備する
3. 画面側に Workers の URL を書く（これは秘密ではない）
4. Workers の許可オリジンに GitHub Pages の URL を書く
5. スマホの実機で、一言 → 写真 → 質問 → 結果まで通す

## 9. 開発初日に決めたこと（2026-10-31 決定）

- 画面は素の HTML / JS で書く。フレームワークもビルド工程も使わない。理由：GitHub Pages にそのまま置け、一人で保守しやすい
- 出力 JSON の項目名は docs/LOGIC.md の 2.3 に案を置いた。英語の項目名、値の文章は日本語
- ルールで決める部分は端末側に置く（2章のとおり）。画面で「建築士の一次判断」を先に見せ、通信なしで試せるようにする
- 家族で共有するリンクは URL に結果を埋め込む方式にする（写真は含めない）。サーバーに何も残さない方針をそのまま保つ。URL が長くなる（数千文字）が、LINE などで送るには足りる見込み
- コミットは main に直接入れる。ブランチとプルリクエストは使わない（一人で作るため）
