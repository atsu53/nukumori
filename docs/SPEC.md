# SPEC｜nukumori 仕様

最終更新：2026-11-04（本人への聞き取りを反映。Q9 工事の大きさの許容、固定の問いと Claude が選ぶ問い、結果の並び、相談シートを結果の結びに、成功の目安の3つ）
位置づけ：ハッカソン開発期間（2026-11-02 12:00〜11-10 14:00 JST）に入る前に固めた仕様。開発中に変えたら、この文書と docs/PROJECT_STATE.md の両方を直す。

## 1. 何を解く問題か

- 離れて暮らす親の家（実家）が寒い。親本人は「古い家だから」「我慢すればいい」で止まり、何が原因でどこから直せばいいか分からないまま冬を越している
- 子ども世代は心配しているが、建築の知識がないので「リフォームしたら？」より先に進めない。工務店に相談するにも、何を頼めばいいかが分からない
- 省エネの指標（UA値・断熱等性能等級）は専門家向けの言葉で、暮らしの実感（冬の朝の室温、お風呂場の寒さ、光熱費、ヒートショック）につながっていない
- nukumori は、親の一言を入口に、写真と数個の質問から「寒さの原因トップ3」と「優先順位つきの改修案」を出し、専門家の言葉を暮らしの言葉に翻訳する

一個人の一言と、社会の数字（2026-11-03 追加）：

- 入口は一個人の親の一言だが、同じ一言は全国で言われている。住宅ストック約5,400万戸のうち、今の省エネ基準を満たす家は約18％、無断熱の家は約24％（国の推計、令和4年度時点。docs/LOGIC.md 6章 A-5b。2026-11-04 に令和元年度の約13％・約29％（A-5）から更新）。WHO は寒い季節の室温を 18℃ 以上にするよう強く勧めている（docs/LOGIC.md 6章 C-3）。高齢者の家庭の浴槽での事故は 11〜4月の冬に集中する（消費者庁。docs/LOGIC.md 6章 C-1・C-2）。つまり「親の家が寒い」は、一軒の事情であると同時に、統計の1件でもある
- 3つの視点を1つの流れに置く：一個人（親の一言、子どもの心配）→ 建築士（原因のルール、改修案の順位、出典のある数値）→ 社会（同じ家が多いこと、施工側の人手の制約、公的な注意喚起と補助）。アプリの画面は一個人の家を診ることに徹し、社会の数字は結果画面の1行（docs/SCREENS.md S5）と README・デモ動画の冒頭と結びに置く。市場規模や死亡者数を画面に並べて不安をあおる使い方はしない
- 出口も社会につながる：工務店に見せる相談シート（S13）は、一軒の情報が施工店に渡る紙。要点の揃った相談は、人手の限られる施工側にも役立つ。ハッカソン後に使い続けるのは、子ども・親・施工店の3者

## 2. 使う人

2026-11-04 の変更（決定：本人）：アプリの言葉から「親」を外し、「住む人の一言」から始まる形にした。自分の家にも、離れて暮らす家族の家にも使える。いちばん多い場面は下の「子ども世代が親の家を見る」使い方で、デモ動画も作者の母の一言から始める（具体的なひとりを外さないため）。画面の言葉は「この家に住む人は、なんて言っていますか（あなた自身の言葉でも）」「次に家を見るとき、確かめてほしいこと」「家族への一言」。家族への一言は「私が心配」を主語にし、家や住む人を責めない（Gemini の調査 2026-11-04 の指摘を取り入れた）。出力の項目名 message_to_parent は互換のため変えない

### 主な使い手：子ども世代（いちばん多い場面）

- 30〜50代。実家から離れて暮らし、帰省や電話で親の様子を知る
- スマホで使う。帰省中に実家で写真を撮りながら答える使い方と、親から聞いた話をもとに自宅から答える使い方の両方を想定する
- 建築の知識はない前提。専門用語は出すとしても必ず説明をつける

### 使わない人：親本人

- 親本人は使えない前提で設計する。小さな文字・多段階の入力・写真のアップロードを親に求めない
- 親に頼むのは「寒い場所を教えてもらう」「写真を撮らせてもらう」までにする
- 結果は子どもが読み、必要なら親に見せられる形（大きな文字の要約）も用意する（5日目以降）

### 間接的な読み手：工務店・リフォーム会社

- 子どもが相談に行くときに見せる「相談シート」の読み手（5日目以降）
- 専門家が読んで違和感のない精度と表現を目指す。断定は避け、現地確認が要ることは明記する

## 3. 入口：住む人の一言（2026-11-04 までは「親の一言」）

- 2026-11-04 の変更：画面の順は「写真 → 親の一言 → 固定の3問 → 建築士が写真を見る」にした（写真が先。本人の「ぱっと写真を撮って入れると現状が返る」という入口の案を採った）。一言がアプリの骨格であることは変えない。場所と時間帯は一言から取り、Claude が選ぶ問いも一言に依る
- 写真のあとの画面で、親が言った言葉をそのまま入れてもらう。例：「お風呂場がさむいんだよぉ」「朝起きると台所が冷蔵庫みたい」「こたつから出られない」
- 入れるのが面倒な人のために、よくある一言を選択肢でも出す（浴室・脱衣所／寝室／台所／居間／廊下・トイレ／家全体）
- この一言から「困っている場所」と「困っている時間帯」を取り出し、以降の質問を絞る。これがアプリの骨格で、ここを削らない

## 4. 入力

### 4.1 写真（任意、最大5枚）

- 必須にしない。写真がなくても質問の答えだけで診断は出す。写真があれば精度が上がる、という位置づけ
- 撮ってほしい順番（画面で案内する）
  1. 寒いと言っている部屋の窓（サッシとガラスが写るように、室内側から）
  2. その部屋の全体（床・壁・天井が入るように）
  3. 浴室の入口と脱衣所（浴室が寒いと言っている場合）
  4. 家の外観（分かれば）
  5. 間取り図（手描きでよい。暖かい部屋から浴室・脱衣所までの経路を読む。2026-11-03 に変更）。なければ気になるところ（結露・隙間・床の冷え・古い暖房器具など）
- 写真から Claude に見てもらうこと：サッシの材質（アルミ・樹脂・木）、ガラスの枚数の手がかり（単板か複層か）、窓の大きさと数、窓の建具の種類（引き違い・掃き出し）、浴室の種類（在来タイルかユニットバスか）、床仕上げ、結露や黒ずみ、暖房器具の種類
- 写真は端末で縮小してから送る（長辺 1,000〜1,200 px 程度）。理由は docs/ARCHITECTURE.md に書く
- 写真はサーバーに保存しない。診断の1回の呼び出しに使って終わり

### 4.2 質問（2026-11-03 に Q0・Q8、2026-11-04 に Q9 を足した）

建築士の目で「これが分かれば原因の大半は絞れる」という項目に限る。

聞き方（2026-11-04 決定・同日実装）：全員に必ず聞くのは Q0 住まいの種類・Q1 築年・Q9 工事の大きさの許容の3問。残り（Q2〜Q8・Q10）は、Claude が写真と間取り図と固定の3問の答えを読んだうえで、答えによって原因や改修案の並びが変わる2〜3問を選んで聞く（受け口 /ask）。写真ではっきり分かること（居間の石油ファンヒーターなど）は聞かずに「写真から読み取ったこと」として画面に見せ、家族の答えと区別して診断に渡す（写真からの推定だけで「ほぼ確実」にはしない）。選んだ問いには「建築士が聞く理由」を1文添える。/ask が失敗したときは、入口の一言で順番を入れ替えて全部聞く形に戻る。現場の建築士が「家を見てから聞くことを決める」のと同じ順にするため。

| 番号 | 質問 | 選択肢 | 何が分かるか |
|---|---|---|---|
| Q0 | その家はどれですか | 一戸建て（持ち家）／マンション・アパート（分譲）／借りている家 | 工事を決められる範囲。分譲や賃貸は窓・外壁の工事に管理組合や大家の了解が要るので、改修案を暖房の工夫と内側の対策に絞り、「まず管理者に相談」を添える（2026-11-03 追加） |
| Q1 | 家はいつごろ建ちましたか | 1980年以前／1981〜1999年／2000〜2015年／2016年以降／分からない | 建った時期の断熱基準のおおよその水準。無断熱か、旧基準かの当たりをつける |
| Q2 | 寒い部屋の窓はどれに近いですか | アルミの枠で、ガラスは1枚／アルミの枠で、ガラスは2枚（ペアガラス）／室内側の枠が白いプラスチック（樹脂）か木で、ガラスは2枚以上／内窓（二重窓）がついている／分からない（写真で判断） | 窓の熱の逃げやすさ。もっとも効きやすい改修の候補を決める |
| Q3 | お風呂はどんなお風呂ですか | タイル張りの昔ながらの浴室／ユニットバス（古い）／ユニットバス（比較的新しい）／分からない | 浴室の寒さの原因と、ヒートショックの注意の強さ |
| Q4 | 脱衣所やお風呂に暖房はありますか | ない／持ち運びのヒーターを使う／浴室暖房乾燥機がある／分からない | 入浴前後の温度差への対策の有無 |
| Q5 | 冬、床の冷たさはどうですか | 靴下でも足が冷たい／スリッパなら平気／気にならない／分からない | 床断熱の有無、床下からの冷え、気密の弱さ |
| Q6 | 冬の朝、窓や壁に結露しますか | 窓がびっしょり／窓の下のほうだけ／壁や押入れにも／ほとんどしない／分からない | 窓の性能と、換気・湿気のたまり方 |
| Q7 | 冬の暖房と光熱費について | 主に使う暖房（エアコン／石油ファンヒーターや開放型ストーブ（排気筒なし）／FF式・煙突つきのストーブ／こたつ・電気ストーブ／床暖房）と、冬の月の光熱費のおおよそ（分かれば） | 暖房の仕方と、改修で下がりうる費用の見当。排気筒のない燃焼器具は水蒸気と空気の汚れが室内に出るので、断熱の提案と換気の注意をセットにする。光熱費は任意（2026-11-03 に暖房の選択肢を分けた） |
| Q8 | 窓やお風呂を直したことはありますか | 窓を交換した・内窓をつけた／お風呂を直した（ユニットバス化など）／どちらも直していない／分からない | 新築時の仕様と改修後の仕様を混ぜないため。直した部位は原因候補と改修案の順位を下げる（2026-11-03 追加） |
| Q10 | 寒さのほかに、直したいところはありますか | 雨漏りや外壁・屋根の傷み／台所・トイレ・お風呂などの古さ／段差や手すりなど暮らしやすさ／特にない／分からない | 一緒に直すと工事がまとまる。勧める案を変える要素として本人が挙げたもの。Claude が選ぶ問いの候補に入れ、答えは相談シートの「家族が優先したいこと」に書く（2026-11-04 追加） |
| Q9 | 工事は、どのくらいまで考えられますか | 工事はしない（暮らし方の工夫だけ）／1日で終わる工事まで／数日かかる工事も考える／大きく直してもよい／まだ分からない | どれだけお金をかけられるか。勧める案を大きく変える要素だが、金額では聞かない（アプリは金額を出さないので、金額で聞いても答えられない）。工事の大きさで予算の感覚を代える。許容を超える案は消さずに「次に直すときに」として下に置く（2026-11-04 追加。選択肢の文言は案） |

- 「分からない」を全問に置く。分からなくても診断は出し、その代わり「確認してほしいこと」として返す
- Q3・Q4 は入口の一言が浴室でない場合、後ろに回すか省く（7問構成）。浴室が入口なら必ず聞く
- Q0 は最初に聞く。分譲・賃貸の答えなら、結果に「窓・外壁などの工事は管理組合や大家の了解が要る。まず管理者に相談」を添え、改修案は「今日できる対策」「脱衣所の暖房」「内窓（了解が取れる場合）」に絞る。初期版は一戸建ての持ち家向けと S0 に明記する
- 家族構成や親の年齢は聞かない。ヒートショックの注意は年齢を問わず出す

## 5. 出力

### 5.1 寒さの原因トップ3

- 原因を3つまで、効いている順に出す。それぞれに「なぜそう考えたか」を1〜2文で添える（例：「アルミ枠の1枚ガラスは、家の中で一番熱が逃げやすい場所です。写真の窓は結露の跡も見えます」）
- 原因の候補（この中から選ぶ。Claude にはこの一覧を渡し、一覧の外の原因を出すときは「その他」として理由を書かせる）
  - 窓から熱が逃げている（単板ガラス・アルミサッシ・大きな窓）
  - 窓まわりの隙間風（建付け・古い引き違い）
  - 床下からの冷え（床断熱がない・弱い）
  - 壁・天井の断熱が足りない（無断熱・薄い）
  - 浴室そのものが冷える（在来タイル浴室・窓が大きい）
  - 脱衣所・廊下・トイレが暖房されていない（部屋ごとの温度差）
  - 暖房の方式が部屋に合っていない（局所暖房だけ・能力不足）
  - 換気や湿気の問題（結露・カビ）
- 「確認してほしいこと」を別枠で出す。分からないと答えた項目や写真で判断がつかなかった点を、次の帰省で見るチェックリストにする
- 確かめてきたら診断し直す（2026-11-04 追加）：帰省で確かめた答えを入れると、前回の見立てを更新し、「何が／前回／今回／どの事実で」変わったかを並べる。確かめ済みの項目は消え、まだ分からないことだけ残る（docs/SCREENS.md S7b、docs/LOGIC.md 2.1）

### 5.2 優先順位つきの改修案

- 3〜5件。それぞれに次を添える
  - 何をするか（暮らしの言葉で）。例：「今の窓の内側にもう1枚窓をつける（内窓）」
  - 期待できる変化（暮らしの言葉で）。例：「窓際のひんやり感と結露が減る。朝の室温の下がり方がゆるやかになる」
  - 工事の大きさの目安：小（1日以内・住みながら）／中（数日）／大（間取りや壁をさわる）
  - 費用の目安：出典のある範囲でしか書かない。書けないときは「工務店に見積りを」とする（金額の根拠は docs/LOGIC.md）
  - 補助制度の有無の目安：あり得る／なし／要確認（制度の最新は窓口で確認、と必ず添える）
- 順位の決め方は docs/LOGIC.md 3.6。ルールは候補と「外さない案・上げない案・許容を超える案」の印だけを出し、並べ方は Claude が家全体を見て理由つきで決める（2026-11-04 に点数の順位をやめた）。考え方は「寒さの原因に直接効くもの」「工事の大きさが許容の中で、住みながらできるもの」「ヒートショックの危険を下げるもの」を上に置く

### 5.3 暮らしの言葉での説明

- 専門用語を使う場面では、必ず暮らしの言葉を先に置き、専門用語はかっこ書きにする。例：「熱の逃げやすさ（UA値）」
- 数値は根拠のあるものだけ使う。根拠のない数値を作らない（docs/LOGIC.md の出典一覧の範囲）
- 断定しない。「〜の可能性が高い」「現地で確認が必要」を使い分ける
- 親への声かけの例を1つ添える（例：「お風呂に入る前に脱衣所を暖めてね、と伝える」）。アプリが家族の会話のきっかけになるようにする
- 言わせないこと（2026-11-04）：「これで暖かくなります」のような効果の約束、工法や製品の指定、「この家は危険」のような不安をあおる言い方、DIY を勧めること（docs/LOGIC.md 3.8）
- 結果の並び（2026-11-04 の本人の説明の仕方から）：建築士は「結論 → 理由 → 選択肢」と「原因 → 対策 → 今日のこと」で話す。画面は「まずこれ（結論1行）→ 原因 → 対策の選択肢 → 今日できること → 相談シート」を案とする（画面の並べ替えは未決。docs/SCREENS.md）

### 5.4 出力の形式（Claude から受け取るもの）

- Claude からは決まった形（JSON）で受け取り、画面側で表示する。自由文で受け取らない
- 項目：原因トップ3（名前・理由・確からしさ）、確認してほしいこと、改修案（名前・説明・期待できる変化・工事の大きさ・補助の目安・順位の理由）、親への声かけ、免責の一文
- 形式の細部は開発初日に決める。設計の考え方は docs/LOGIC.md と docs/ARCHITECTURE.md

## 6. 範囲の切り分け

### 6.1 MVP：4日目（11/5）までに必ず動くもの

- 入口の一言 → 写真（任意・最大5枚） → 質問（5〜7問） → 診断中 → 結果（原因トップ3・確認してほしいこと・改修案・親への声かけ）
- スマホのブラウザで動く。ホーム画面に追加できる（PWA の最低限：マニフェストとアイコン。オフライン動作は求めない）
- Cloudflare Workers 経由で Claude API を呼ぶ。API キーは Workers のシークレットのみ
- 結果を画面に保存する（端末内。ブラウザの保存領域）。サーバーには何も残さない
- 免責の表示：「このアプリは建築士の知識にもとづく目安を示すもので、現地調査や設計・工事の判断に代わるものではない」

### 6.2 5日目以降（11/6〜11/9）に足すもの

優先順。上から順に着手し、間に合わないものは落とす。

1. ヒートショックの注意：浴室・脱衣所が入口のときに、入浴の注意（脱衣所を暖める・湯温・時間）を公的な出典つきで出す
2. 工務店に見せる相談シート（2026-11-03 に 5 から繰り上げ。家族の事実と AI の推測を分けて書く。構成は docs/SCREENS.md の S13）。2026-11-04 決定：おまけの機能でなく、結果の最後に必ず出す（このアプリは工務店に見積もりを頼む前の段階に使うもの）。デモの終わりもここ
3. 断面の室温シミュレーター：家の断面図（屋根・壁・窓・床）を簡略に描き、改修前後で冬の朝の室温のイメージがどう変わるかを見せる。数値は出典のある関係式の範囲で、イメージであることを明記する
4. 改修前後の比較：改修案を選ぶと、原因トップ3のうちどれが解消され、暮らしがどう変わるかを並べて見せる
5. 補助制度の案内：国の住宅省エネキャンペーン（年度ごとに名前と内容が変わる）と環境省の断熱リフォーム支援を、制度名と公式 URL で案内する。金額は書かず「最新は窓口で確認」とする
6. 家族で共有するリンク：結果を兄弟姉妹と共有する。サーバーに保存しない方針との両立が要るので、URL に結果を埋め込む方式か、Workers の短期保存かを開発中に決める。間に合わなければ画像保存で代える

### 6.3 やらないこと

- 新築向けの診断（置く、とだけ決めている。今回は作らない）
- 正確な UA値の計算や省エネ計算書の作成（アプリの目的ではない。数字は「目安」として使う）
- 工事費の見積り（工務店の仕事。アプリは範囲と考え方を示すだけ）
- 親本人が操作する画面
- アカウント登録・ログイン・サーバーへの保存
- 室温・光熱費の数値の予測（前提のない数字は誤解を生む。断面の図は「仕組みの模式図」にとどめる。2026-11-03 の調査の取り込みで確定）
- 見積書の比較、介護保険の住宅改修、融資、夏の暑さ、センサー連携（README の「今後」に1行ずつ書く）

## 7. 守ること

- 会社の案件データ・社名・顧客情報を一切使わない。使うのは建築士の知識と公開の法令・行政資料のみ
- 数値は出典のあるものだけ。出典が確認できない数値は書かない（docs/LOGIC.md）
- 写真と回答はサーバーに保存しない。Claude API への送信は診断のときの1回のみ
- 法令や補助制度は「確認時点」を添え、最新は窓口で確認するよう案内する
- 医学的な判断はしない。ヒートショックは公的機関の注意喚起をそのまま引く

## 8. 成功の目安（自分で見るための基準）

- 親の一言を入れてから結果が出るまで、スマホで3分以内
- 原因トップ3と改修案を、建築士が読んで「おかしくない」と言える
- 使い終えた子どもが、次の3つをできるようになる（重さは同じ。2026-11-04 決定）
  - 寒さの理由が分かる：「古い家だから」でなく、どこから何が逃げているかを説明できる
  - 今夜から親を守れる：脱衣所を暖めるなど、工事の前にできることを親に伝えられる
  - 工務店に相談できる：相談シートを持って、工務店に「内窓をつけたい」のように具体的に言える（見積もりを頼む前の段階）
