# SCREENS｜nukumori 画面の流れ

最終更新：2026-11-07 夜（2回目の録画から表紙・結果の帯・工務店に相談する画面を直した。午後は、結果を結論カードから始まる1画面にし、確認項目を押して答える形にし、文章に上限を入れた。下の「2026-11-07 の変更」）
前提：スマホの縦画面。片手で親指だけで進められること。1画面1つの用事。戻るボタンは常に置く。

## 全体の流れ

```
S0 はじめに（家族の家／自分の家をここで選ぶ。2026-11-07 夜）
 → S2 写真（任意。2026-11-04 に一言より先にした）
 → S1 親の一言
 → S3 質問（固定の3問、1問1画面）
 → S3a 建築士が写真を見ている（/ask）→ S3b 見えたこと → S3 Claude が選んだ2〜3問（2026-11-04）
 → S4 診断中
 → S5 結果（2026-11-07 から1画面：結論カード → 断面図 → 原因 → 間取り図 → 改修案 → 今日できること → 確かめてほしいこと → 家族への一言。旧 S5・S6・S7）
   → S7b 帰省で確かめてきたこと（押して答える）→ S4 再診断 → S5 の先頭に「変わったところ」（2026-11-04）
 → S8 家のカルテ（2026-11-07 夜。旧 保存・共有 → 工務店に相談する）
（5日目以降）S9 ヒートショックの注意／S10 断面シミュレーター／S11 改修前後の比較／S12 補助制度／S13 相談シート
```

MVP は S0〜S8。S9 以降は docs/SPEC.md の 6.2 の順で足す。

## 2026-11-07 の変更（本人の本番の画面収録から。実装済み nukumori d0351ec）

本人がスマホで通した録画は14分24秒で、「使い方がすっと入ってこない」「文字が多い」「相談シートが長い」が指摘。直したのは次の8つ。

- 結果は1画面（S5・S6・S7 を1つにした。コードの S6・S7 は S5 の別名）。先頭に結論カード（原因1つ／まず相談する案1つ／今日できること1つ）、次に家の断面図、その下に「原因の見立て」「間取り図で見ると」「まず相談するなら、これ」「今日からできること」「確かめてほしいこと」「家族への一言」の順。原因の理由と改修案の説明は「くわしく」の中
- S3b「見えたこと」は、写真1枚ごとに「見えた」「分からない」の短い句（各25字以内）を並べ、文章は出さない。「あと n 問」のボタンを先頭にも置く
- S7b は入力でなく、確認項目ごとに Claude が書いた2つの答え（例：2枚だった／1枚だった）と「まだ」を押す。ひとことは任意の1行
- 再診断のあとの画面では「診断し直す」のボタンを出さず、「保存・共有」だけにする（録画で、同じ位置のボタンを2回押して同じ入力をやり直していた）。もう一度足すときは下の小さなリンクから
- Claude の文章に字数の上限（worker/prompt.js の「書き方」）。原因の理由40字、改修案の説明40字、確認項目は題16字＋やり方45字、写真の所見は見えた／分からない各30字。母の事例で生成文は 1,910字 → 876字、写真を読む段は 731字 → 399字
- 相談シートは2層。コピーするのは短い版（約450字。聞くこと・困っていること・家のこと・確かめたこと・見立ての要点・現地で見てほしいこと）。詳しい版（写真の所見・理由・見積の分け方・補助）は「詳しい版」を開いてコピー
- S2 に「まとめて選ぶ（5枚まで）」。選んだ順に空いている枠へ入る。1枚ずつの「選ぶ」も残す
- 固定の文：国の推計の1行は S0 へ。消費者庁の注意は1行＋リンク。免責の脚注は S0 と S8 だけ
- 出力の形の変更（worker/schema.js）：photo_notes と photo_findings は {photo, seen, unknown}、checks は {what, how, yes, no}。端末に残っている古い結果（文のままの checks）も読める
- 母の写真で4回流し、選ばれた問い（q2・q4・q5）、原因の順（浴室そのもの／脱衣所・廊下／床下）、最初の案（脱衣所・浴室の暖房）はすべて同じだった
